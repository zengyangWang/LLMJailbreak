### LibreTranslate 翻译服务启动与使用指南

本项目的 Translate 攻击模块默认连接 `http://127.0.0.1:47891`。下面给出在无 sudo 的场景下，使用 Docker 拉起服务的完整步骤（含镜像代理、非持久化与持久化两种启动方式）、验证方法、与本项目联动以及常见问题排查。


## 一、前置条件
- 已安装 Docker，并能以当前用户运行（`docker ps` 正常）。
- 网络环境允许从镜像代理或 DockerHub 拉取镜像（若直连超时，可使用镜像代理域名）。


## 二、拉取镜像（使用国内代理，避免超时）

```bash
# 从 DaoCloud 代理拉取官方镜像
docker pull docker.m.daocloud.io/libretranslate/libretranslate:latest

# 标记为官方命名，便于后续使用
docker tag docker.m.daocloud.io/libretranslate/libretranslate:latest libretranslate/libretranslate:latest
```

（你也可以用其他代理域名，命令相同；若可直连 DockerHub，则直接 `docker pull libretranslate/libretranslate:latest`）


## 三、启动服务（两种方式）

已验证“非持久化”方式可行，命令如下：

### 方案 A：非持久化（最快，容器删除后会重新下载模型）
```bash
docker rm -f libretranslate 2>/dev/null || true

docker run -d --name libretranslate --restart unless-stopped \
  -p 47891:5000 \
  -e LT_LOAD_ONLY="en,zh,fr,es,ja,de,ru" \
  -e LT_UPDATE_MODELS=1 \
  libretranslate/libretranslate:latest
```
说明：
- `-p 47891:5000` 将容器 5000 端口映射到宿主 47891（本项目默认连接这个端口）。
- `LT_LOAD_ONLY` 限制只加载必要语种，减少模型体积与下载时间。
- `LT_UPDATE_MODELS=1` 首次启动自动下载/更新模型。
- 无数据卷挂载，删除容器后会重新下载模型。

### 方案 B：持久化（推荐，避免重复下载模型）
```bash
# 创建持久化卷
docker volume create libretranslate_data

docker rm -f libretranslate 2>/dev/null || true
docker run -d --name libretranslate --restart unless-stopped \
  -p 47891:5000 \
  -e LT_LOAD_ONLY="en,zh,fr,es,ja,de,ru" \
  -e LT_UPDATE_MODELS=1 \
  -v libretranslate_data:/home/libretranslate/.local/share/argos-translate \
  libretranslate/libretranslate:latest
```
说明：
- 官方镜像默认以 `libretranslate` 用户运行，对应家目录在 `/home/libretranslate`。请将数据卷挂载到该用户目录（如上），避免权限问题。
- 首次启动会下载模型并缓存到卷中。之后重启/升级容器无需重复下载。


## 四、验证服务

```bash
# 查看容器状态与日志（首次启动需等待模型下载完成）
docker ps
docker logs -f libretranslate

# 服务就绪检查：应返回语言列表（JSON）
curl http://127.0.0.1:47891/languages

# 简单试译：英 -> 中
curl -s -X POST http://127.0.0.1:47891/translate \
  -H 'Content-Type: application/json' \
  -d '{"q":"hello","source":"en","target":"zh"}'
```

## 六、常用运维命令

```bash
# 查看日志 / 状态
docker logs -f libretranslate
docker ps

# 重启 / 停止 / 删除
docker restart libretranslate
docker stop libretranslate
docker rm -f libretranslate
```

## 七、常见问题排查

- 拉取镜像超时/被拒：使用代理域名（如 DaoCloud）拉取并重标记；或配置 Docker 守护进程镜像加速（需要管理员设置 `/etc/docker/daemon.json`）；或联系网络管理员开通代理。
- `docker: permission denied while trying to connect to the docker API`：当前用户未加入 `docker` 组或会话未刷新。让管理员将你加入 `docker` 组，然后执行 `newgrp docker` 再重试；或在具备权限的机器上运行。
- `curl 127.0.0.1:47891` 连接失败：
  - 检查容器是否在运行：`docker ps`；
  - 查看日志是否仍在下载模型：`docker logs -f libretranslate`；
  - 确认端口映射：`docker inspect -f '{{ .HostConfig.PortBindings }}' libretranslate`，应有 `5000/tcp:[{HostPort:47891}]`；
  - 若端口被占用，改用其他端口：`-p 47900:5000`，并在本项目中保持默认（无需修改，仍连本机 47891 时，请同步调整映射）。
- 权限问题（挂载卷写入失败）：请确保挂载路径是 `/home/libretranslate/.local/share/argos-translate`（镜像内普通用户有写权限）；避免挂载到 `/root`。
- 首次启动等待下载：看到 “Loaded support for ... languages ...” 和 gunicorn “Listening at ...:5000” 即服务就绪，再进行验证与调用。
